# Line6 자동 생성 패키지

## v0.4 메서드 경로 문법 수정

절대 경로에서 참조 연산자 `&`는 경로 맨 앞이 아니라 Method 이름 바로 앞에 둬야 한다. 이전 버전의 잘못된 `&.Models.Model.BK_Probe`를 `.Models.Model.&BK_Probe`로 수정했다. 문법 설정·소스 로드·컴파일 검사·오류 처리·제어 연결의 다섯 경로를 모두 수정했다. 상대 참조 `&StartStats`는 올바르므로 유지했다.

근거: SimTalk Operators and Expressions의 reference operator 항목은 "For object paths you have to insert the reference operator & directly in front of the name of the Method or the Variable"이라고 명시하며, Method 문서에도 `.Models.Model.&MyMethodWithoutParameters` 예제가 있다. 이는 문서로 확인한 코드 오류의 수정이며, 전체 2201 실행 성공을 뜻하지 않는다.

## v0.3 안정성 개편

- 긴 문자열을 Program에 대입하는 경로와 COM SetValue 코드 입력을 제거했다.
- ASCII `.st` 파일을 Method.load로 읽으며, 작은 메서드의 로드·컴파일·실행 사전검사를 먼저 수행한다.
- 전체 메서드를 먼저 생성한 뒤 파일을 모두 읽고 각 메서드의 hasSyntaxError를 검사한다.
- 종료시간은 EndTime으로 지정하며, 자동 검증은 애니메이션과 실시간 지연 없이 실행한다.
- 기존 보존식 검사에 실제 내부 NumMU 합계와 실행 중 최대 WIP 검사를 추가했다.
- 실패 시 이 자동화가 생성한 시뮬레이션을 정지하고, build.log와 last-step.txt가 있는 폴더를 연다.
- PowerShell 7.4.7에서 실제 구문검사 및 자동화 보조 함수의 정상/실패 경로 테스트를 실행했다. Windows PowerShell 5.1 및 Plant Simulation 2201 실행 검증과는 구분한다.

## 실행
Windows에서 ZIP 압축을 풀고 START.cmd를 더블클릭한다. Plant Simulation 2201 설치와 유효한 라이선스가 필요하다. 별도 COM 인스턴스에 새 모델을 생성한다. 기존 열려 있는 모델은 읽거나 저장하지 않는다. 기본 바탕화면의 Line6_BK_날짜시간 폴더에 결과를 저장하고 Plant Simulation을 열어 둔다. 보안 정책이 스크립트 실행을 차단하면 조직 정책을 우회하지 말고 build.log 또는 메시지를 전달한다. START.cmd는 해당 프로세스의 스크립트 실행 옵션만 지정하며 시스템 정책을 변경하지 않는다.

## 중요한 상태
작성 환경은 Linux이며 Plant Simulation에서 이 패키지를 실행하지 못했다. 실행하면 생성 및 검증을 시도하는 자동화이지, 이미 검증된 .spp 파일이 아니다. 자동화 API는 공개 예제와 2504 도움말로 교차 확인했으나 2201의 모든 속성 호환성이 확인된 것은 아니다. 오류 시 build.log가 생성되며 완성으로 표시하지 않는다. UNVERIFIED.spp는 중간 산출물이다. 최종 DETERMINISTIC.spp는 사용자 PC에서 9개 검증이 실제 통과해야만 생성된다.

## 모델 근거
논문 그림12: MoveCab6.1 →605→610→615→620→625→630→635→640→645→MoveCab6.2. 그림13: 하강→665→670→Robot6C.1. 출구는 로봇 직후로 선택했으며 이후 6C.1~6C.5 버퍼 및 Line7은 제외한다. 논문 7.1의 선택된 concept2는 각 조립 위치 capacity1, PT=one takt의 모델링이다. 6A167초/6C137초를 이 모델링 가정으로 적용하며 실측 개별 작업시간으로 주장하지 않는다. MoveCab 두 위치의 시간0은 추가 가정이다. 6A 연속 컨베이어의 엄밀한 동기 이동은 구현되지 않았다.

중간 버퍼는 B개의 단일 수용 위치다. B2=[10,30]초, B3=[10,10,30]초, B4=[10,10,10,30]초, B5=[10,10,10,10,30]초. 논문 4.4.1의 앞쪽10초 위치 추가 방식을 따른다. 5개 슬롯을 배치하고 LiftRoute가 마지막 B개만 사용한다. 나머지 슬롯은 비활성 경로로 비어 있다. 버퍼 용량 외 추가 이동 스테이션으로 저장공간을 중복 추가하지 않는다. 상승70/복귀35초, 하강55/복귀64초. 복귀는 실제 출발 후 다음 진입 가능 시점에 적용한다.

11개6A위치+2개승강설비+3개6C위치+B슬롯으로 모델 수용량16+B. 실제 공장 전체의 확정된 수용량이라는 뜻은 아니다. B는2~5 정수, K는1이상 정수. 변경은 Reset 후에만 한다. 초기 상태는 빈 라인이다. 논문의 초기 버퍼2대 조건과 다르다. 초기 재공품을 수동으로 추가하면 안 된다.

Source 간격1초, 외부대기 슬롯1개, 출구 무제약의 포화공급 국소 조건이다. 외부 대기는 OutsideQueue 도착 이후만 측정하며 Source 내부 공급 대기나 주문 backlog를 뜻하지 않는다. 실제 공장의 Push/Pull은 확정하지 않는다.

## 제어와 검증
입구 실제 도착에 WIP++, 최종 Drain 도착에 WIP--. 구간 내부 모든 위치를 포함한다. K도달 시 입구를 잠그며 출구에서 카드 반환 후 개방한다. 입력값 및 WIP 보존/상한을 검사한다. 각B의 무제어와 K=16+B의 완료량·평균WIP 일치 및 K1을 자동 확인한다. 이 검증은 확률적 정지·동시 이벤트 전체에 대한 증명이 아니다.

Touch는 준비기간을 제외한 WIP/중간버퍼/외부대기량 시간적분을 수행한다. 완료수와 시간당처리량을 계산한다. 체류시간은 측정기간 진입·완료 제품만 계산하므로 미완성 제품 수와 함께 보고하며 편향이 있다. 종료 코호트 추적은 미구현이다. BlockSeconds는 마지막6A위치의 막힘시간, WaitSeconds는 첫6C위치의 대기시간이므로 전체 라인 동기정지시간과 동일하다고 주장하지 않는다.

## 실험 설정
검증은 준비1시간+측정2시간의 결정론적 실행9개. 저장된 연구용 초기 설정은 준비24시간(미검증 가정), 측정355운영시간(논문5주×5일×14.2시간)이다. 준비기간 선정은 아직 실증되지 않았다. 같은 조건으로 B와 K를 변경해 탐색할 수 있으나 자동 전체 민감도 분석/신뢰구간/최소B·K선정은 아직 구현하지 않았다.

## 확률모델 제한
앤돈은 해당 라인 전체를 정지시키는 근거가 있지만 이 버전에는 확률적 정지를 넣지 않았다. 원 분포 파라미터 의미와2201인수 대응이 검증되지 않은 상태에서 임의 정지분포를 넣지 않는다. Wait-in/out 정지자료를 중복 입력하지 않는다. 따라서 이 결정론적 모델만으로 CONWIP/버퍼의 실무상 최적값이나 논문의 확률적 생산량을 결론내릴 수 없다. 확률적 반복100회와 paired CI, 공통정지 중첩 복구 검증은 후속 작업이다. 비용·실제 증설가능성·판매증가도 이 모델로 확정하지 않는다.

## v0.2 수정
2201에서 메서드 코드 입력 중 발생한 `Wrong number of parameters: 1 passed (string), 0 expected`를 우회하도록 COM SetValue 경로를 제거했다. 매개변수 없는 ExecuteSimTalk 호출로 객체 변수의 Program에 직접 대입하고, SimTalk 2.0을 명시한다. 모든 Method를 먼저 만든 뒤 코드를 입력하고, 입력한 원문을 다시 읽어 확인한다. 오류 로그에는 마지막 SimTalk 명령을 남긴다. 사용자 환경에서 이 수정의 실제 실행 성공은 아직 확인되지 않았다.
